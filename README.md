# Isaac Projects

Robotics simulation project built on **Isaac Sim 6.0.1 + Isaac Lab 3.0.0-beta2** (with ROS2 Jazzy
for the navigation part). The goal is **pick & place of metal brackets** with a **FANUC
M-710iD/50M mounted on a rail and a custom two-claw gripper** (`right_claw` / `left_claw`, each with
a thumb and a forefinger), trained in simulation with reinforcement learning.

The repository holds the hand-written work: the USD cell, the Isaac Lab training package, the
support scripts and the guides in `workspace_notes/`. The engines (Isaac Sim, Isaac Lab, pixi) are
not versioned and are reinstalled from the recipes described below.

**Development machine**: Windows 11, RTX A4000 (16 GB).

### `myProjects/Manipolazione/`

| Path | Contents |
|---|---|
| `CAD/` | Source `.step` files (robot, staffatrice, staffe) — input of the Isaac Sim CAD Converter |
| `Apps/Simulation/` | The hand-built cell, in USD: `robot.usd` (FANUC + rail imported from CAD), `gripper.usd`, `apps.usd` (assembly), `robotApps.usd` and its variant `robotApps_local.usd` (used by training, with the arm stored locally instead of fetched from the content server) |
| `Apps/Props/` | Scene assets: the brackets (`staffa_quadrata.usd`, `staffe.usd`), the `Grid` environment, the SICK Visionary-T Mini sensor and the `m710id_50m` configuration |
| `Apps/Training/` | Isaac Lab package (external project generated by `isaaclab.bat --new`), see below |
| `Scripts/ScriptEditor/` | ~48 utilities to **paste into the Isaac Sim Script Editor**: they act on the Stage selection (physics, Joints, units/scale, measurements, contact diagnostics). Index in `Scripts/ScriptEditor/README.md` |
| `Scripts/SimulationScripts/` | **Standalone** scripts (they open a `SimulationApp`): Motion Generation examples and Tutorial 9 (gripper, trajectory, follow target, pick & place with cuMotion and PINK) |
| `Scripts/*.py` | One-off diagnostics on the Isaac Lab environment (per-claw errors, `ee_frame` offsets, joint limits, link names…). Index in `Scripts/README.md` |

The two kinds of script have different execution models — those in `ScriptEditor/` do not run
outside Isaac Sim — and must not be mixed.

### `Apps/Training/` — the training task

```
Apps/Training/
├── scripts/                  → programs to launch from a terminal
│   ├── list_envs.py, zero_agent.py, random_agent.py
│   └── rsl_rl/               → train / play with RSL-RL (PPO)
└── source/Training/Training/ → Python package (installed with pip install -e)
    ├── robots/apps.py        → robot configuration (articulation, initial pre-grasp pose)
    ├── props/                → square-bracket configuration
    └── tasks/manager_based/move_to_grasp/
        ├── move_to_grasp_env_cfg.py, arm_descriptor.py, gripper_descriptor.py
        ├── config/apps/      → task and PPO configuration
        └── mdp/              → actions, observations, rewards, terminations, events,
                                stages (stage machine), claw_geometry
```

The registered task is **`Move-To-Grasp-Apps-v0`**: the arm starts from a fixed pre-grasp pose and
has to grasp a square bracket (CAD ring, 0.45 m side) lying on the floor, following a stage
machine (align → slide → descend) enforced on the actions, not only on the rewards. How each
module and parameter works is documented in `workspace_notes/ARCHITETTURA_APPS_PREGRASP.md`.

## The three environments — they are not interchangeable

| Task | Use | Launch |
|---|---|---|
| ROS2 bridge, standalone scripts | **pip** Isaac Sim inside the pixi workspace | `pixi run sim` from `IsaacSim-ros_workspaces/jazzy_ws` |
| **CAD import**, Script Editor work on the cell | **Standalone** Isaac Sim in `C:\isaacsim` | `C:\isaacsim\isaac-sim.bat` |
| **RL training** | **Isaac Lab 3.0.0-beta2** in `IsaacLab/` | `isaaclab.bat` |

Both Isaac Sim copies are `6.0.1-rc.7`, so USD files move freely from one to the other. Isaac Lab
installs its packages **into the Python bundled in `C:\isaacsim`** (no conda, no venv) and creates the
symlink `IsaacLab/_isaac_sim` → `C:\isaacsim`. As a consequence Isaac Lab and the CAD workflow share
the same set of dependencies: if a script or the CAD Converter fails on a dependency (numpy, pillow,
psutil), that is the first suspect.

## Installation on a new machine

The complete procedure is in `workspace_notes/INSTALLAZIONE_ISAACSIM_601_ROS2_JAZZY_PIXI.md`. In short:

# ROS2 Jazzy + Isaac Sim (pip) via pixi
git clone https://github.com/isaac-sim/IsaacSim-ros_workspaces.git
# then: cd IsaacSim-ros_workspaces/jazzy_ws && pixi install && pixi run build

# Standalone Isaac Sim 6.0.1 in C:\isaacsim  (needed for the CAD Converter)

# Isaac Lab — the branch matters
git clone -b release/3.0.0-beta2 https://github.com/isaac-sim/IsaacLab.git
# then: symlink IsaacLab/_isaac_sim -> C:\isaacsim and install with isaaclab.bat
```

Two version traps:

- **Isaac Lab `main` (2.3.2) targets Isaac Sim 5.1, not 6.0.1.** On the wrong branch Kit tries to
  download an extension that only exists in 5.1 and fails on the network: the error looks like an
  SSL/proxy problem but is not. Check the branch before investigating the network.
- **Isaac Lab 3.0 starts headless by default** (the opposite of 2.x). Without `--viz kit` no window
  appears and the script stays in the simulation loop, which looks exactly like a hang.

The USD paths in the training code (`robots/apps.py`, `props/staffa_quadrata.py`) are absolute and
point to `C:\Projects\...`: the repository must be cloned into `C:\Projects`.

## Daily use

**Training** (from `Apps/Training/`, with the Isaac Lab environment):

```powershell
isaaclab.bat -p scripts\zero_agent.py --task Move-To-Grasp-Apps-v0 --viz kit   # environment sanity check
isaaclab.bat -p scripts\rsl_rl\train.py --task Move-To-Grasp-Apps-v0 --viz kit
isaaclab.bat -p scripts\rsl_rl\play.py  --task Move-To-Grasp-Apps-v0 --viz kit
```

**ROS2** (Navigazione only) — three terminals, in this order, from `jazzy_ws`:

```powershell
pixi run zenoh             # T1: Zenoh RMW router — MANDATORY, start it first
pixi run sim               # T2: Isaac Sim with the ROS2 bridge, then Play
pixi run ros2 topic list   # T3: verify the bridge
```

The Zenoh router is needed even locally: with `rmw_zenoh_cpp` all discovery goes through
`rmw_zenohd`, and without it `ros2 topic list` shows nothing.
